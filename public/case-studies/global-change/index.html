Functional Mini-Site Prototype for Global Change

Overview

Project

Global Change Research Program Website Redesign

Timeline

Q2 2022 - Q3 2022

Team

UX Designer, UX Architect, Content Strategist, Developer

Role

UX Architect

A federal mandate required public sector websites to align with the United States Web Design System (USWDS). The Global Change website needed a full redesign to meet these standards, but the existing site was outdated in both structure and accessibility.

Instead of relying on static mockups, we built a fully interactive prototype. This allowed stakeholders to experience navigation, layout, and interactive behavior in a real environment before committing to full development.

Tech Stack

  • HTML
  • CSS
  • Markdown
  • Contentful
  • Jekyll
  • Netlify
  • GitHub

Problem

The existing workflow relied heavily on static designs, making it difficult to validate navigation across multiple pages, test responsive behavior across devices, and understand how real content would affect layouts. As a result, feedback arrived late, design decisions relied on assumptions, and accessibility and usability issues were often discovered later in the process.

Context and Constraints

The project ran for about a year in collaboration with the Global Change web team.

Key constraints:

Stakeholder Expectations

Stakeholders responded more effectively to interactive prototypes than static mockups, requiring a realistic and navigable experience.

Design System Requirements

The prototype needed to be built using an existing USWDS-based design system to maintain consistency and test its effectiveness in a real-world implementation.

Pattern Constraints

The design system accelerated development but limited customization, requiring careful decisions about when to extend existing components versus create new ones.

Project Scope

The site contained a large amount of content and multiple page types, making navigation, content hierarchy, and content modeling critical to success.

My Role

My main focus was turning design guidelines into reusable, production-ready components that teams could consistently use.

I worked closely with both designers and developers to define how the design system would be implemented, maintained, and evolve over time.

Owned Outright
  • Building a functional, multi-page prototype using HTML, CSS, and JavaScript
  • Applying and extending components from the US Web Design System
  • Creating new components when needed (while maintaining accessibility standards)
Shared Ownership
  • Integrating dynamic content using Contentful
  • Connecting everything into a cohesive, navigable experience

Solution

To reduce uncertainty and gather earlier feedback, I collaborated with designers and developers to create a realistic, multi-page prototype that closely reflected the final product. We built on the existing design system, integrated Contentful to support real content, created custom components where needed, and used Jekyll to generate production-like pages from structured content. This allowed the team to validate navigation, responsiveness, and content early in the design process.

Engineering Challenges & Solutions

Modeling Content Before Templates

Challenge: Existing website content didn't map cleanly to the new page templates, making it difficult to build reusable layouts.

Decision: Defined reusable content models in Contentful before designing and implementing page templates.

Outcome: Created a scalable content structure that reduced rework and made templates more flexible.

Extending the Design System

Challenge: Some project requirements couldn't be met using the existing USWDS components alone.

Decision: Designed and built new components that followed USWDS design tokens, accessibility standards, and interaction patterns.

Outcome: Expanded the design system while maintaining a consistent, accessible experience across the product.

CMS-Driven Prototyping

Challenge: Static content couldn't accurately represent how the site would behave once content was managed through a CMS.

Decision: Integrated Contentful into the prototype and used Jekyll to generate production-like pages from structured content.

Outcome: Stakeholders could evaluate navigation, layouts, and content workflows using realistic content before development began.

Accessibility in Custom Components

Challenge: Extending the design system with custom components introduced the risk of inconsistent or inaccessible interactions.

Decision: Applied accessible interaction patterns, including keyboard navigation, semantic ARIA attributes, and focus management.

Outcome: New components met accessibility standards while remaining consistent with the rest of the design system.

Impact

The interactive prototype changed how stakeholders evaluated the redesign.

Instead of reviewing static mockups, they could navigate real user flows, interact with content, and experience responsive layouts directly. This led to:

Earlier feedback on navigation and content organization

Validation of layouts using real content rather than placeholder text

Identification of usability issues before development

Greater stakeholder confidence in design decisions

Validation of the internal design system on a large, content-heavy site

Key Takeaways and Reflection

One of the biggest lessons from this project was the value of involving content strategy early. Understanding how content would be structured before designing page templates helped reduce rework, influenced layout decisions, and created a stronger foundation for the CMS.

The project also showed the strengths and limitations of static site generation. Jekyll was a great fit for building realistic, content-driven prototypes, but it made it more difficult to explore complex interactions and dynamic experiences. If I were rebuilding this today, I would consider using a framework like React to better support interactive components while keeping the same content-first approach.

More broadly, this project reinforced that a successful design system is about more than creating reusable components. The best results come from aligning content, design, and technical constraints early—leading to better collaboration, more realistic prototypes, and stronger design decisions.
